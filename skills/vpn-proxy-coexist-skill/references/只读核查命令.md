# 只读核查命令

以下命令在 Windows PowerShell 中按需运行，不修改网络设置，不要求安装工具。输出只在本机分析；分享前去掉机器标识、企业地址和非必要连接信息。

## 状态与版本

记录客户端“关于”页面中的版本，以及 VPN、TUN、系统代理三个开关。不要只靠进程存在判断 VPN 已连通。内核版本与客户端版本应分别确认。

```powershell
Get-NetAdapter | Select-Object ifIndex, Name, Status
Get-NetIPInterface -AddressFamily IPv4 |
  Select-Object InterfaceIndex, InterfaceAlias, ConnectionState, InterfaceMetric

# 只查看代理是否开启及监听地址，不导出整个注册表
$ProxyKey = 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings'
Get-ItemProperty -LiteralPath $ProxyKey -Name ProxyEnable, ProxyServer |
  Select-Object ProxyEnable, ProxyServer
```

## DNS 端口的真正所有者

```powershell
Get-NetUDPEndpoint -ErrorAction Stop |
  Where-Object LocalPort -In 53,1053 |
  Select-Object LocalAddress, LocalPort, OwningProcess
Get-NetTCPConnection -State Listen -ErrorAction Stop |
  Where-Object LocalPort -In 53,1053 |
  Select-Object LocalAddress, LocalPort, OwningProcess

# 把上面实际 PID 填入；只取进程名，不输出可能带凭据的命令行
$ListenerPid = [int](Read-Host '监听进程 PID')
Get-Process -Id $ListenerPid | Select-Object Id, ProcessName
```

结合应用绑定错误判定争用。命令失败应报告，不能把失败当成“没有监听”。未使用 1053 的环境应改查实际端口。

## 系统 DNS、指定 DNS 与实际路由

```powershell
$InternalHost = Read-Host '实际公司域名，仅输入主机名'
$CorporateDns = Read-Host '已核实的公司 DNS 地址'
Resolve-DnsName -Name $InternalHost -Type A -DnsOnly
Resolve-DnsName -Name $InternalHost -Server $CorporateDns -Type A -DnsOnly

# 填入实际故障连接的目标 IP，不能拿任意公网 IP 代替
$DestinationIp = Read-Host '该次连接实际目的 IPv4'
Find-NetRoute -RemoteIPAddress $DestinationIp
Test-NetConnection -ComputerName $DestinationIp -Port 443 -InformationLevel Detailed
```

`Test-NetConnection` 只证明指定 TCP 端口的结果；它不验证 TLS、域名证书、认证或本机执行。存在 AAAA/IPv6 时也核查对应 DNS、路由与连接，不能只凭 IPv4 正常排除故障，更不能默认关闭 IPv6。

捕获 fake IP 冲突时，在故障发生期间连续短时采样实际目的地址的 `Find-NetRoute`，保留时间、前缀、接口、下一跳。动态路由可能在单次静态检查前已经消失。

## 系统代理绕过与显式代理不是同一种测试

在 PowerShell 7/.NET 对应实现中，可辅助查看当前默认代理的选择：

```powershell
$TargetUri = [uri](Read-Host '实际 HTTPS 测试网址')
$Proxy = [System.Net.Http.HttpClient]::DefaultProxy
if ($null -eq $Proxy) {
  '没有默认代理'
} else {
  $Proxy.GetProxy($TargetUri)
}
```

不同运行时有不同返回约定：可能返回空值或原目标表示直连。不要只看 `IsBypassed`，应结合对应运行时文档、浏览器实际连接和应用业务结果。此检查也不能代表所有浏览器、服务进程或显式代理客户端。

如已确认本机 HTTP 代理端口，可做传输对照，测试目标优先使用用户本来就在访问的服务：

```powershell
$TestUrl = Read-Host '实际 HTTPS 测试网址'
$LocalProxy = Read-Host '本机 HTTP 代理地址，例如 http://127.0.0.1:端口'
curl.exe --proxy $LocalProxy --connect-timeout 5 --max-time 10 --output NUL --write-out '%{http_code}\n' $TestUrl
curl.exe --noproxy '*' --connect-timeout 5 --max-time 10 --output NUL --write-out '%{http_code}\n' $TestUrl
```

后一条禁用 curl 的显式代理；TUN 开启时仍可能进入 TUN。前一条不遵循 Windows 系统绕过名单，不能用它验证公司域名是否绕过。不要添加 `-k` 跳过证书验证；TLS 失败应按真实错误定位。

403/302 仅说明该次 HTTP 往返到达了一个服务，未证明登录、数据访问或长连接成功。避免复制带 token、查询参数或认证头的完整命令。

## Codex 与 dot

通过产品现有界面分别检查聊天、工作空间、本机权限和电脑在线状态。在本机日志中只提取对应时间段的事件类型与重连次数，不公开整段原文。

不要把裸 `codex remote-control --json` 当只读状态命令：该路径可能启动服务、发起注册或写锁文件。传统远控注册的 MFA/403 错误也不能直接解释 dot 的 Local Work executor 故障。

最终由用户向 dot 发起“读取本机当前时间，不创建或修改文件”等只读任务。不能用在当前终端执行同一命令代替 dot 通道验收。
